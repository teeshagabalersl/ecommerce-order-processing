# E-Commerce Order Processing System

## Overview

The E-Commerce Order Processing System is a Java Spring Boot application that uses RabbitMQ to process orders asynchronously. It demonstrates topic-based message routing, independent consumers, manual acknowledgments, duplicate order detection, and dead-letter queue (DLQ) processing.

Users can place orders through a simple web interface by selecting a product category and entering a quantity.

## Technologies Used

- Java 21
- Spring Boot
- RabbitMQ
- Maven
- HTML
- CSS
- JavaScript

## Architecture

The application uses a RabbitMQ topic exchange named `orders_exchange` to route order messages to the appropriate queues.

### Components

- **Order Service:** Creates orders and publishes messages with a unique order ID in the RabbitMQ `message_id` property.
- **Inventory Service:** Receives orders from all supported categories, validates quantities, and handles duplicate orders.
- **Analytics Service:** Receives electronics orders, records valid electronics sales, and ignores invalid or duplicate orders.
- **Dead-Letter Consumer:** Logs invalid inventory orders routed to the dead-letter queue.

### Message Routing

| Component | Queue | Routing Key |
|---|---|---|
| Inventory Service | `inventory_queue` | `order.created.*` |
| Analytics Service | `analytics_queue` | `order.created.electronics` |
| Dead-Letter Consumer | `orders_dead_letter_queue` | Messages routed through `orders_dlx` |

The Inventory Service receives orders from all supported categories. The Analytics Service receives only electronics orders.

The order ID is included in the RabbitMQ `message_id` property, allowing consumers to identify orders and detect duplicates independently of the message body.

The inventory queue is configured with the dead-letter exchange `orders_dlx`. When an invalid inventory message is rejected without requeueing, RabbitMQ routes it to the dead-letter queue.

## Prerequisites

Ensure the following are installed:

- Java 21
- Maven or the Maven Wrapper included in the project
- RabbitMQ Server

RabbitMQ must be running locally and accessible on port `5672`.

The RabbitMQ Management UI is available at:

`http://localhost:15672/`

The application uses the following configuration in `src/main/resources/application.properties`:

```properties
spring.application.name=ecommerce-order-processing
server.port=8080
spring.rabbitmq.host=localhost
spring.rabbitmq.port=5672
spring.rabbitmq.username=guest
spring.rabbitmq.password=guest
spring.rabbitmq.listener.simple.acknowledge-mode=manual
spring.rabbitmq.listener.simple.prefetch=1
```

## How to Run

### 1. Start RabbitMQ

Start your local RabbitMQ server and confirm that it is running.

Open the RabbitMQ Management UI:

`http://localhost:15672/`

### 2. Start the Spring Boot Application

Open the project in IntelliJ IDEA and run:

`EcommerceOrderProcessingApplication.java`

Alternatively, run the application from the project root using the Maven Wrapper:

```bash
./mvnw spring-boot:run
```

If Maven is installed and configured on your machine, you can also use:

```bash
mvn spring-boot:run
```

The application starts on port `8080`.

### 3. Open the Web Interface

Visit:

`http://localhost:8080/`

Select a category, enter a quantity, and submit the order.

## API Endpoint

### Place an Order

**Endpoint:** `POST /api/orders`

**Parameters:**

| Parameter | Description | Example |
|---|---|---|
| `category` | Supported product category | `electronics` |
| `quantity` | Number of items ordered | `2` |

### Example Request

```bash
curl -i -X POST "http://localhost:8080/api/orders?category=electronics&quantity=2"
```

### Example Response

```json
{
  "orderId": "generated-order-id",
  "category": "electronics",
  "quantity": 2
}
```

The actual order ID is generated by the application and differs for each new request.

### Invalid Category Example

```bash
curl -i -X POST "http://localhost:8080/api/orders?category=a.b&quantity=2"
```

**Expected result:** HTTP `400 Bad Request`. Unsupported categories are rejected and are not published to RabbitMQ.

## Testing

### Test Case 1: Electronics Order Processing

**Objective:** Verify that an electronics order is processed by both the Inventory and Analytics services.

**Steps:**

1. Start RabbitMQ and the Spring Boot application.
2. Open the web interface.
3. Select `electronics`.
4. Enter quantity `2`.
5. Submit the order.
6. Check the IntelliJ console.

**Expected result:**

- The Inventory Service reserves inventory.
- The Analytics Service records the electronics sale.
- Both messages contain the same order ID.

**Expected console output:**

```text
Inventory Service: Reserving inventory for order <order-id>, category: electronics, quantity: 2
Analytics Service: Recording high-value electronics sale for order <order-id>
```

**Status:** Pass when both consumers process the same order ID.

### Test Case 2: Clothing Order Processing

**Objective:** Verify that a clothing order is routed only to the Inventory Service.

**Steps:**

1. Open the web interface.
2. Select `clothing`.
3. Enter quantity `3`.
4. Submit the order.
5. Check the IntelliJ console.

**Expected result:**

- The Inventory Service reserves inventory.
- The Analytics Service does not process the clothing order because its queue is bound only to `order.created.electronics`.

**Expected console output:**

```text
Inventory Service: Reserving inventory for order <order-id>, category: clothing, quantity: 3
```

**Status:** Pass when the order is processed by Inventory only.

### Test Case 3: Invalid Order and Dead-Letter Queue

**Objective:** Verify that an order with a negative quantity is rejected and logged through the dead-letter queue.

**Steps:**

1. Open the web interface.
2. Select `electronics`.
3. Enter quantity `-1`.
4. Submit the order.
5. Check the IntelliJ console.

**Expected result:**

- The Inventory Service rejects the invalid order without requeueing it.
- The Analytics Service logs `Invalid order ignored` and does not record an invalid sale.
- The Error Logger logs the order routed to the dead-letter queue.
- All three messages refer to the same order ID.

**Expected console output:**

```text
Inventory Service: Invalid quantity for order <order-id>
Analytics Service: Invalid order ignored: <order-id>
Error Logger: Invalid order <order-id> routed to DLX
```

The order of the log messages may vary because the consumers process messages independently.

**Status:** Pass when the invalid order is rejected by Inventory, ignored by Analytics, and logged by the DLQ consumer.

### Test Case 4: Duplicate Order Handling

**Objective:** Verify that the same order is not processed more than once by each consumer during the current application run.

**Steps:**

1. Start RabbitMQ and the Spring Boot application.
2. Open the RabbitMQ Management UI at `http://localhost:15672/`.
3. Navigate to **Exchanges** and select `orders_exchange`.
4. Scroll to the **Publish message** section.
5. Set the routing key to `order.created.electronics`.
6. Set the payload to:

   ```text
   DUPLICATE-TEST-001|electronics|2
   ```

7. In the **Properties** section, add the message ID property:
    - Property name: `message_id`
    - Property value: `DUPLICATE-TEST-001`

8. Click **Publish message**.
9. Publish the exact same message a second time without changing the routing key, payload, or message ID.
10. Check the IntelliJ console.

**Expected result:**

- The first publication is processed by the Inventory and Analytics services.
- The second publication is identified as a duplicate and ignored by both consumers.
- The duplicate messages use the same order ID as the original messages.

**Expected console output:**

```text
Inventory Service: Reserving inventory for order DUPLICATE-TEST-001, category: electronics, quantity: 2
Analytics Service: Recording high-value electronics sale for order DUPLICATE-TEST-001
Inventory Service: Duplicate order ignored: DUPLICATE-TEST-001
Analytics Service: Duplicate order ignored: DUPLICATE-TEST-001
```

The order of the log messages may vary.

**Important:** The `message_id` property is required because the consumers read the order ID from RabbitMQ message properties. Publishing the payload without this property will cause the consumers to reject the message as malformed.

Duplicate tracking uses in-memory sets. Publish both messages without restarting the application.

## Configuration

The application uses the following listener settings:

```properties
spring.rabbitmq.listener.simple.acknowledge-mode=manual
spring.rabbitmq.listener.simple.prefetch=1
```

- **Manual acknowledgment:** Consumers acknowledge successfully handled messages.
- **Prefetch count of 1:** Each consumer receives one unacknowledged message at a time.
- **Dead-letter exchange:** Rejected inventory messages are routed to the configured dead-letter exchange.
- **Duplicate detection:** Consumers use in-memory sets of processed order IDs to avoid processing the same order twice during the current application run.
